# SNS Research Loop Bootstrap v1

This is the only institutional text that should be duplicated into the external scheduler. The scheduler substitutes one `loop_id`; evolving law remains in the repository.

The canonical rendered prompt is produced by `automation.orchestration.render_bootstrap_prompt(loop_id)`.

## Bootstrap sequence

1. Invoke the connected GitHub repository tool against `xxx3r/SNS-S-S` before any environment-blocker claim.
2. Read accepted `main` and `AGENTS.md`.
3. Resolve the one active contract whose front matter matches the requested `loop_id`. Never hard-code a contract filename or version in the scheduler prompt.
4. Read only the compact state authorized by stable law and that contract, including current executable schemas, runtime manifest, research graph, and current delegation/authorization state when relevant.
5. Execute one bounded transaction under one-owner and authority law.
6. New receipts use the current repository receipt schema and the canonical inspectable state-snapshot primitive. Placeholder state digests are forbidden.
7. Recheck accepted source, governance/delegation, graph readiness, and live PR ownership before publication. Repository-hosted validation is the evaluator when local execution is unavailable.
8. Use Google Drive only when the selected contract or a concrete pending decision explicitly requires a relevant SNS artifact.
9. Report attempted connector operations, created or consumed artifacts/authority, receipt ID, terminal state, limitations, and one exact handoff.

## Design rule

The platform prompt is a fire starter, not a second copy of the laboratory constitution. Month-specific issues, PR numbers, queue lore, contract versions, routing algorithms, schema shapes, and scientific policy belong in version-controlled repository authority.
